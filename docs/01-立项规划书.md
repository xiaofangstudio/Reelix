# 01 · 立项规划书

## 一、这是什么

**Reelix** 是小方工作室创作软件线里的一款桌面**特效合成**软件，主对标 **After Effects / Fusion / Nuke**，副对标 **Premiere Pro**。

但它不是两款软件，是**一款**。合成与剪辑在 Reelix 里不是两个模块，是**同一份数据的几种看法**：下半区「时间线」看时间顺序，属性面板的「效果栈」看处理链顺序。

> **⚠️ 定位修正（用户明确纠正）：** 原先把 Reelix 写成「剪辑与特效合体的视频软件」，重心偏到了剪辑。用户原话：「**这并不是一个剪辑软件，还是特效合成软件，别忘了！！**所以说特效合成里面的**识别扫描 3D 空间场景**这种最基础的需要有。」因此本文档已改为**合成优先**：Reelix 的身份是**特效合成**，剪辑是它的附属能力（因为做合成必须能摆镜头顺序）。完整说明见 [10-特效合成与空间识别.md](10-特效合成与空间识别.md)。

## 二、为什么是「合成优先」

这是这一款产品存在的**唯一理由**。如果只是做一个剪辑器，市面上已经有很多；如果只是做一个合成器，也一样。Reelix 的价值在于把这两件事之间那堵墙拆掉——但**墙两边的主次必须分清：合成是主体，剪辑是附属**。

### 现状的痛

用 After Effects 加 Premiere 做片子，实际工作流是这样的：

1. 在 Premiere 里剪好时间线
2. 发现某个镜头需要加一个合成
3. 把那个镜头单独导出去，或者用 Dynamic Link 跳到 After Effects
4. 在 After Effects 里新建一个合成，把素材放进去，摆图层、加效果，调参数，打关键帧
5. 渲染出来，导回 Premiere
6. 发现时间点对不上，或者长度要改
7. 回 After Effects 改，重新渲染，重新导回
8. 重复 3 到 7

这条来回的路上，**时间被吃掉的是等待，不是创作**。而且更麻烦的是心智负担：你有两个时间线、两个项目文件、两套关键帧、两套撤销栈，你要时刻记住「我现在在哪个软件里」。

### Reelix 的做法

**同一个项目、同一份数据、同一个窗口。** 剪辑和特效之间的关系不再是「导出与导入」，而是「同一份数据上的两个位置」。

具体见 [04-剪辑与特效融合设计.md](04-剪辑与特效融合设计.md)，这里只说结论：

- 一个项目文件，不是两个
- 一份数据模型（内部是一张有向无环图做求值，界面呈现为图层 + 效果栈）
- 一套关键帧引擎，片段参数和效果参数共用
- 一套撤销栈，剪辑操作和特效操作在同一个历史里
- 两种看法（时间线轨道、图层树与效果栈）实时双向联动，选一个高亮另一个

## 三、要做的事

### 必须做到

1. **可实时预览的图层合成 + 效果栈。** 拖效果到片段、改参数、立刻在监视器上看到结果。延迟要低到可以边拖滑块边看效果。**这是 Reelix 的主体，不是附属。**
2. **识别扫描 3D 空间场景。** 从实拍视频里反推摄像机运动与场景三维结构（相机追踪 / SfM / 三维重建）。合成里所有「把三维元素钉进实拍画面」的工作都建立在这上面。技术路线见 [10](10-特效合成与空间识别.md)。
3. **摄像机 + 视频 2D→3D 空间场景转换。** 解算出的相机是一台可用的三维摄像机；平面视频能转成有深度、可摆三维元素的空间（相机反投 / 深度分层）。见 [10](10-特效合成与空间识别.md) 4.2 / 4.3。
4. **关键帧 + 曲线编辑器。** 任何数值参数都能打关键帧，用的是同一套曲线引擎与同一个曲线编辑器。**没有关键帧的合成软件不成立。**
5. **蒙版与形状遮罩。** 钢笔遮罩、矩形/椭圆遮罩、羽化、扩展、反转、遮罩跟踪。**这是合成的基本功，不准少。**
6. **色度抠图（色键）。** 简单的绿幕/蓝幕抠像：取色、容差、边缘羽化、溢色抑制、去杂边。**用户点名要，必须易用。**
7. **粒子系统。** 发射器、发射速率、寿命、初速度、重力、尺寸/透明度随生命周期变化、湍流；支持从图层或形状发射。见 [02](02-功能规格.md)。
8. **录音（音频录制）。** 软件内直接麦克风录音，录进时间线音频轨，带输入设备选择、电平表、监听开关。见 [02](02-功能规格.md) 模块 C。
9. **多轨时间线与剪辑。** 修剪、拖拽、切割、吸附、多轨排列、复合片段。**这是附属能力**，但因为做合成必须能摆镜头顺序，所以它必须内建、必须帧精确。
10. **预设特效与素材文件夹。** 效果 / 动画 / 调色可存为预设；「上传素材」根目录含音效、音乐、图像、视频、字体、预设、工程，进软件即出现在预设面板。见 [10](10-特效合成与空间识别.md) 第六节。
11. **GPU 合成。** 多轨混合、转场、调色、色键、变换、粒子，全部走 GPU。CPU 路径只作为兜底。
12. **硬件加速解码。** 用系统解码器（Windows 上是 D3D11VA），帧解码延迟要压到毫秒级。
13. **导出。** H.264 / ProRes 等常用格式，导出时能选分辨率、码率、色彩空间。编码器直接做进 Reelix，不另做独立编码软件。
14. **一份项目文件走天下。** `.reelix` 自包含引用关系，换机器只要素材路径可达就能打开。

### 应该做到

15. **2D 特征点追踪与视频稳定。** 稳定是追踪的副产品，投入小、用户感知强。
16. 音频波形显示与帧精确的音画同步、多轨音量/淡入淡出
17. 色彩管理（至少支持 LUT 与基础色彩空间转换）
18. 文字与图形层（标题、字幕、基础矢量形状）、三维文字
19. 示波器（波形图、矢量示波器、直方图）

### 可以晚一点

20. **稠密重建（MVS）**：从相机与图像生成深度图 / 网格。重，但空间识别的下一层。
21. 镜头效果（光晕、景深、镜头畸变）
22. 多机位剪辑

## 四、明确不做的事

以下方向经过讨论后砍掉，**不再排期**，写在这里是为了防止有人手痒。

| 不做 | 原因 |
| --- | --- |
| **AI 功能**（智能剪辑、AI 抠像、生成式改写） | 整个产品线无生成式 AI。**例外**：字幕走本地离线语音转写（sherpa-onnx + SenseVoice），只做「语音 → 带时间戳文字」，不联网、不生成内容 |
| **云端协作 / 账号体系** | 完全本地优先，不做服务器 |
| **自动更新** | 用户装了哪个版本就是哪个版本 |
| **自由三维建模与材质系统** | 自己从零建模型、做 PBR 材质，技术门槛与人力投入远超当前规模。**注意：这不等于不做三维**——Reelix 要做的「识别扫描 3D 空间场景」是从实拍**反推**摄像机与场景结构，与「从零建模」是两件事，前者是必做项。 |
| **独立编码器软件** | 导出能力直接做进 Reelix |
| **插件市场** | 首版不做，接口预留但不开放分发 |
| **移动端** | 重度合成软件在手机上没意义 |
| **网页版** | 必须是真的桌面应用，不是浏览器壳子 |

## 六、为什么现在做

1. **底座是宽松许可，这是创作线里少见的。** 清单里说得很清楚：创作线上真正能整包拿来二开的只有三个，Reelix 的底座是其中之一。这意味着 Reelix 可以按「改造」估算工期，而不是按「从零自研」估算。
2. **它的底座已经被验证过能跑。** Clypra 是一个完整可用的剪辑器，不是玩具工程，时间线、解码、合成、导出都有真实实现。
3. **它是整条线里技术含量最高的一款。** 先啃硬骨头，抽出来的东西（GPU 合成、帧缓存、曲线引擎、撤销栈）能反哺 Kinexa 与 Strata。
4. **它和 Kinexa 分工清楚，不重叠。** Kinexa 管逐帧与矢量动画，负责把角色画动；Reelix 管镜头与合成，负责把画好的东西剪成片子。两者是上下游关系。

## 七、风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| **融合模型做错方向** | 整个产品失去存在理由 | M3 之前先用最小原型验证双向联动与共享关键帧，验证不过就调整模型，不要硬推 |
| **实时预览性能不达标** | 特效没法「边拖边看」，体验退化回两个软件 | 代理分辨率 + 帧缓存 + 脏标记求值三件套，性能不达标不上新功能 |
| **GPL 污染** | 整个仓库无法以 MIT 交付 | 严格走 [docs/06](06-参考项目与许可边界.md) 白名单，新依赖一律先查许可 |
| **范围失控** | 烂尾 | 严格按 [docs/08](08-里程碑与验收.md) 里程碑推进，一次只做一个 |
| **FFmpeg 是 LGPL-2.1** | 静态链接会传染 | **只能动态链接**，且必须保留许可证文件与源码获取途径 |
