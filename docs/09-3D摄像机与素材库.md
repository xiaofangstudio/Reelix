## 一、体积预算修订：150MB

| 项目 | 预算 | 说明 |
| --- | --- | --- |
| 主程序 + Tauri 壳 | 15 MB | Rust 编译产物，strip + lto |
| FFmpeg 动态库 | 35 MB | 只带解码所需的几个 dll，不打包完整版 |
| wgpu / 着色器 / WGSL | 3 MB | 自研模块 |
| **内置字体** | 40 MB | 中文按**子集化**打包（**GB2312 全集 6763 字 + 常用符号**，规格见 3.5 节），不是整包 |
| 预设动效 / 转场 / 缓动 | 2 MB | 纯 JSON |
| LUT 色彩预设 | 5 MB | .cube 文件 |
| 3D 预览（three 相关） | 3 MB | 打进前端 bundle |
| 图标 / UI 资源 | 3 MB | 矢量为主 |
| 余量 | 44 MB | 留给版本迭代 |
| **合计** | **150 MB** | 硬上限 |

**子集化是硬规则。** 中文字体整包动辄 20MB 一款，直接塞五款就爆。所有中文字体必须用 `fonttools pyftsubset` 做子集，只保留常用字表。构建脚本里跑，产物入库，源字体不入库。**中文字体每款只带 1–2 个字重**（Regular + Bold），这是六款中文能塞进 40MB 的前提。字号表与参数见 3.5 节。

## 二、3D 摄像机（重磅功能）

### 2.1 为什么它必须是「重磅」

Reelix 的定位是**特效合成软件**（合成优先，剪辑是附属）。用户做片头、MV、产品演示时，最想要的效果就是**镜头运动**——
图层在空间里分层，摄像机推拉摇移，前后景自然产生视差。

这在 Premiere 里做不到，在 AE 里要靠「3D 图层 + 摄像机层」手工搭。Reelix 要把它做成**一条开箱即用的摄像机图层**。

### 2.2 技术路线（不自研引擎，整合开源）

**结论：不自己写 3D 引擎，用成熟开源库整合。**

| 用途 | 选型 | 许可证 | 理由 |
| --- | --- | --- | --- |
| 前端 3D 预览视口 | `three` | **MIT** | 事实标准，WebGL/WebGPU 双后端 |
| React 绑定 | `@react-three/fiber` | **MIT** | 声明式写场景，和 Reelix 的 React 前端同构 |
| 3D 操作器（手柄/轨道控制） | `@react-three/drei` | **MIT** | 自带 OrbitControls、TransformControls、Gizmo、Grid，直接可用 |
| Rust 侧矩阵/四元数 | `glam` | **MIT / Apache-2.0** | 相机矩阵、投影矩阵、逆矩阵；已有 wgpu 上直接用 |
| 帧缓存与合成 | 复用 Reelix 自研 `wgpu_compositor` | — | 见 `06-参考项目与许可边界.md` |

[@react-three/fiber 的许可证为 MIT，仓库为 `pmndrs/react-three-fiber`。](https://www.npmjs.com/package/@react-three/fiber?activeTab=code)

**不引入**：Babylon.js（体积与生态取舍）、任何 GPL 的 3D 软件内核（如 Blender、Natron）。

### 2.3 摄像机模型（AE 式，但更简单）

> **本应用不需要「完整 3D 建模」。** 摄像机服务的是**平面素材的空间摆放**，不是建模。

**摄像机图层**（时间线上的一条摄像机轨道，类型 `Camera`）：

| 参数 | 单位 | 可关键帧 |
| --- | --- | --- |
| 位置 X / Y / Z | px（Z 支持负数） | 是 |
| 目标点 X / Y / Z | px | 是 |
| 焦距 | mm（等效 35mm，默认 50） | 是 |
| 方向模式 | 单节点 / 双节点（目标点）｜**摄像机术语，非图节点** | 否 |
| 景深 | 开关 | 是 |
| 光圈 / 对焦距离 / 模糊层次 | — | 是 |
| 运动模糊 | 开关 + 快门角度 | 是 |
| 视角预设 | 活动摄像机 / 正面 / 顶部 / 左侧 / 自定义 | 否 |

**图层 3D 化**：任何片段（Clip）右键可勾选「启用 3D」，随后多出六组属性——
位置 XYZ、旋转 XYZ、缩放、方向（朝向相机 / 自由）、锚点、接受光照开关。未勾选的图层老老实实待在 Z=0 平面。

**视差是自然结果**：Z 越大的图层，镜头横向移动时位移越小（远）；Z 越小（近），位移越大。

### 2.4 与「图层 + 效果栈」的关系

摄像机不是独立模块，它**就是一条特殊图层（摄像机图层）**，与其它图层共处同一个图层树与时间线：

```
图层树
├─ 摄像机（Camera）
├─ 片段A（启用 3D）
├─ 片段B（启用 3D）
└─ 文字（3D）
```

各图层按 Z 深度排序后交给 3D 合成求值，摄像机决定观察矩阵。对应关系：

| 用户做的事 | 图层树 / 时间线上看到 | 效果栈 / 属性面板看到 |
| --- | --- | --- |
| 添加摄像机 | 时间线顶部多一条「摄像机」轨道，显示相机的「穿过」区间 | 图层树顶部多一条「摄像机」图层 |
| 拖拽相机位置 | 摄像机轨道的属性条数值变化 | 属性面板里的位置参数同步变化 |
| 给相机的焦距打关键帧 | 时间线上出现关键帧点 | 曲线编辑器里出现曲线 |
| 图层勾选 3D | 片段左侧出现 3D 角标 | 效果栈上方多出「3D 变换」参数组 |

**判据不变**：如果用户需要手动「同步」两个地方，那就是做错了。

### 2.5 3D 视图怎么放

监视器（模块 B）顶部标签页扩为四挡：

```
[ 合成 ]  [ 活动摄像机 ]  [ 四视图 ]  [ 图层 ]
```

- **合成**：最终画面（默认）
- **活动摄像机**：以相机视角看，所见即所得
- **四视图**：左上正面 / 右上顶部 / 左下左侧 / 右下活动摄像机，每个格子可用 `three` 的 OrbitControls 自由转动
- **图层**：图层树 + 效果栈的调试视图，显示各图层的 Z 深度顺序与效果链，排查前后景遮挡关系用

3D 视图是**预览**，不是最终渲染入口。导出永远走 `wgpu` 渲染管线，不走 WebGL 截图——这一点必须在代码注释里写死，否则会有人图省事用 `toDataURL` 截图导出，画质和精度全丢。

### 2.6 首版范围（M2 交付，M1 只留接口）

**做**：单/双节点相机、焦距、位置、目标点、图层 3D 变换、Z 排序、四视图、相机关键帧、景深（近似实现）。

**晚做**：光照与材质、阴影投射、真正的景深散景（先做高斯近似）、3D 文字挤出、相机父子绑定。

**不做**：建模、布尔运算、骨骼、粒子物理、GLTF 导入（除非以后明确要）。

## 三、内置字体库

### 3.1 选字原则

只收**商用免费**字体，且许可证必须是 OFL / MIT / Apache-2.0 或明确声明可商用。逐款核对许可证，把许可证原文一起放进 `scaffold/src-tauri/assets/fonts/<字体名>/LICENSE.txt`（构建时随 `bundle.resources` 打进安装包，清单见该目录下的 `MANIFEST.md`）。

用户付了钱也好没付钱也好，字体版权风险由 Reelix 兜住——**绝不能让用户因为用了内置字体被追责**。

### 3.4 字体界面必须有的功能

1. **字体预览**：列表里每个字体名用该字体自身渲染，不显示英文名。
2. **中文标注**：字体卡片上标明「可商用」角标 + 许可证缩写（OFL）。
3. **缺失字提示**：用户输入的字如果该字体没有，立刻在文字框上方黄条提示「以下 3 个字在该字体中不存在，已回退到思源黑体」，而不是静默回退。
4. **收藏与最近使用**：字体列表顶部固定「最近使用」与「收藏」两组。
5. **导入自定义字体**：支持用户导入 .ttf/.otf/.ttc，导入时弹窗提示「请自行确认该字体的商用授权」——把责任说清楚，不假装是我们的问题。
6. **子集化**：内置中文字体全部走子集，用户输入生僻字时回退到系统字体并在状态栏标注。

### 3.5 子集化规格（已定，不再浮动）

中文字体子集的**字号表已拍板**：

| 项 | 取值 |
| --- | --- |
| 汉字 | **GB2312 全集 6763 字**（一级 3755 + 二级 3008） |
| 西文与数字 | ASCII `0x20`–`0x7E` 全量 |
| 标点与符号 | 中英标点、数字序号、货币、单位、箭头、制表符、常用数学符号（≈300 字形） |
| 字重 | 中文每款 **1–2 个**（Regular + Bold）；西文每款 3 个（Light / Regular / Bold） |
| 产物格式 | 中文 `.ttf` / `.otf` 子集入库；另转一份 `.woff2` 供界面内预览用 |
| 工具与参数 | `fonttools pyftsubset --layout-features='*' --glyph-names --symbol-cmap --legacy-cmap`（保留 kerning 与常见 OpenType 特性） |
| 时机 | **构建期**完成，产物入库、源字体不入库；运行时不做字形裁剪（与 [11](11-硬指标与优化手感建议.md) 第 12 条一致） |
| 兜底 | 超出子集范围的字 → 回退思源黑体子集 → 再回退系统字体，并在状态栏标注（见 3.4 第 6 条） |

**为什么是 6763 而不是 3500：** 3500 字只覆盖现代汉语常用字，人名、地名、专有名词很容易掉字；Reelix 的文字层要做标题与字幕，掉一个字的观感代价远大于多出来的十几 MB。

### 3.6 Reserved Font Name 改名规则（合规红线）

OFL 的 **Reserved Font Name（RFN）** 条款规定：**修改版（子集化属于修改版）不得继续使用保留字名**。逐款核对结果：

| 字体 | 是否有 RFN | 子集化后的处置 |
| --- | --- | --- |
| 霞鹜文楷 LXGW WenKai | **有**（`霞鹜`/`霞鶩`/`落霞孤鹜`/`LXGW`），且附加条款只对「**仅供网页字体交付**的子集」放宽 | **必须改内部字体名**，界面以「基于 霞鹜文楷」标注来源 |
| 得意黑 Smiley Sans | **有**（`Smiley`/`得意黑`） | **必须改内部字体名**，界面以「基于 得意黑」标注来源 |
| Inter | 无 | 可保留原名 |
| JetBrains Mono | 无 | 可保留原名 |

**结论**：内置子集统一使用中性内部名（如 `Reelix Serif SC` / `Reelix Hei SC`），在字体卡片上以「基于 XXX（OFL）」的说明行注明来源与许可——既守 RFN，又让用户看得懂这是什么字体。

## 四、预设动效库

### 4.1 三类预设

| 类别 | 数量（首版） | 存储形式 | 说明 |
| --- | --- | --- | --- |
| 缓动预设 | 30 | JSON（cubic-bezier 控制点） | 标准 / 缓入 / 缓出 / 弹跳 / 回弹 / 过冲 |
| 转场预设 | 12 | JSON + WGSL 参数 | 叠化 / 推 / 划像 / 缩放 / 故障 / 光晕 |
| 文字动效 | 8 | JSON（关键帧模板） | 打字机 / 逐字浮现 / 弹入 / 抖动 / 手写 |

**全部是数据，不是代码。** 一个预设 = 一段关键帧 JSON + 参数范围，应用时注入到目标属性的曲线上。这样用户能直接看到预设「拆开」后的关键帧，也就能改——比黑盒预设强得多。

### 4.2 参考与整合

| 来源 | 用途 | 许可证 |
| --- | --- | --- |
| `gre/bezier-easing` | 缓动算法参考 | MIT |
| `lottie-web` | 允许用户导入 Lottie 动画 | MIT |
| AE 自带的缓动曲线命名习惯 | 预设命名对齐（缓入、缓出等词用户熟） | 仅命名参考 |

**不许**抄 Adobe 的预设文件（`.ffx` 等），那些是有版权的资源。预设值由我们自己算。

### 4.3 LUT 色彩预设

自带 20 组 `.cube` 文件（胶片、清透、日系、赛博等类别）。**只用公开发布为 CC0 / MIT 的 LUT**，或者自研生成。商用 LUT 包一律不收。

## 五、布局原则（不参考剪映）

用户明确要求：**不参考剪映，要让人上手就会用。**

### 5.1 三条布局信条

1. **可见即可得**：所有核心动作都必须有可见的按钮。快捷键是加速器，不是唯一入口。任何功能如果只能通过快捷键触达，就是设计缺陷。
2. **不隐藏**：不把功能塞进「更多」菜单。菜单最多两层。找不到的功能 = 不存在的功能。
3. **不用行业黑话**：文件名用「素材」，不要叫「媒体池」；用「片段」，不要叫「剪辑事件」；「导出」不叫「渲染输出」。首次出现的专业词（如「复合片段」）旁边带一个问号，悬停显示一句大白话解释。

### 5.2 与同类软件的区别

| 软件 | 它的做法 | Reelix 的做法 |
| --- | --- | --- |
| 剪映 | 大按钮、傻瓜化，但深度功能藏得深 | 大按钮起步，深度功能**同级可达**，不用切换模式 |
| Premiere | 功能平铺但特效要跳去 AE | 特效就在同一个界面，下半区切标签页即可 |
| AE | 一切围绕图层与时间轴，剪辑弱 | 时间线是一等公民，图层与效果栈和它同源 |
| DaVinci | 底部导航切页，切换成本高 | 上半区固定不变（素材/监视器/属性），只动下半区视图 |

### 5.3 首次使用

首次打开只显示**一个按钮**：「导入素材开始」。不要教程、不要模板墙、不要登录弹窗。拖动第一个视频进来之后，用**一行的浮层提示**（不是弹窗）告诉用户「按空格播放，把素材拖到下面的时间线」。提示只出现一次，用户操作过就不再出现。
