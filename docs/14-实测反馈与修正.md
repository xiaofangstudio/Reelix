## 进编辑器之前先问帧率和尺寸

`App.tsx` 挂载后调一次 `bootstrapProject()`，紧接着就把四区编辑器铺开了，没有任何开场。用户要的是像 Strata 那样的开场：先把工程定下来，再进剪辑界面。

Strata 对应的东西是 `UI/NewCanvasSheet.swift`——新建文档时先出一张表，选画布尺寸与预设，确认才落进主界面。Reelix 要抄的是这个形状，不是它的字段（Strata 是图像软件，没有帧率一说）。

开场要提供的东西：

| 字段 | 可选值 | 默认 |
| --- | --- | --- |
| 工程名 | 文本 | 未命名项目 |
| 分辨率 | 3840×2160 / 2560×1440 / 1920×1080 / 1280×720 / 1080×1920 竖 / 1080×1080 方 / 自定义 | 1920×1080 |
| 帧率 | 23.976 / 24 / 25 / 29.97 / 30 / 50 / 59.94 / 60 | 25 |
| 色彩空间 | Rec.709 / Rec.2020 / sRGB | Rec.709 |

这四个值现在硬写在 `new_project` 里，开场界面要把它们变成入参传进去。`docs/02-功能规格.md` 第 342 行早写了「什么都没选 → 序列设置（分辨率、帧率、色彩空间）」，把这条从属性面板挪一部分到开场，口径是对得上的。

开场同时要有「打开最近工程」与「打开已有工程…」。没有工程时就停在开场，不要露一堆空面板在后面。现在没工程时的时间线提示是「还没有打开工程，先「新建工程」或「打开工程」」，这句话应该属于开场，不该是编辑器里的一条孤儿文案。

## 图标不是拿来自由发挥的

`src-tauri/icons/` 里只有一个 4,576 字节的 `icon.ico`，是 Tauri 脚手架自带的默认图标，不是用户给的。用户为此单独发了一次火。

他给的图是 1084×1084 的正方，四边一圈亮黄绿描边，宽 40px、占边长 3.69%，色值 `#aeff00`；里面是 `#3d3d3d` 的深灰底；正中是白色「R」与「L」组成的花押。

要做的是把这张图转成多尺寸 `.ico`（16 / 24 / 32 / 48 / 64 / 128 / 256）覆盖 `src-tauri/icons/icon.ico`，`tauri.conf.json` 里的 `"icon": ["icons/icon.ico"]` 不动；桌面快捷方式的图标跟着换，任务栏和「应用和功能」里也要是它。`docs/07-安装与打包.md` 第 32 行的规矩是只留 `.ico`，别再往仓库里塞 `icns` 和多尺寸 png。

有一点要分清：`#aeff00` 是这张图标的用色，不是 Reelix 的界面强调色。界面仍然只准中性白加浅绿（`#26734f` 对白底文字、`#57c08f` 填充按钮）。换句话说，不要因为「`#aeff00` 也是绿」就顺手把它提成 UI 强调色，也不要把用户给的图标改成品牌绿——logo 用它自己的颜色，`docs/05-界面规范.md` 对品牌色的例外写得就是这个意思。

## 交付以双击能跑起来的那份为准

这次真正的问题只有一句：代码写了，东西没编出来，用户拿到的是三小时前的壳。所以这一版起，验收对象是桌面快捷方式双击开的那个进程，不是仓库里的源码。

交付前自己要跑一遍完整动作：双击 Reelix → 走开场建工程 → 导入素材 → 拖上轨道 → 切一刀 → 撤销 → 关窗，然后在任务管理器确认关窗后无残留进程。`npx tsc --noEmit` 零错误、`cargo clippy` 零 warning、`cargo test` 全过照旧。

红线再念一遍：配色白底加 `#26734f` 与 `#57c08f`，不许出现紫色；Reelix 是特效合成软件，界面里没有节点图、没有连线；全中文界面；无 AI、无账号、无自动更新；不执行任何 git 提交或推送；没有流体或液态相关的东西。

## 出可分发包必须打开 custom-protocol

这条是这次才摸出来的，以前没记过：只跑 `cargo build --release` 是不够的。

`scaffold/src-tauri/Cargo.toml` 里 `default = ["desktop"]`，而 `tauri` 自己的 `build.rs` 是按 `custom-protocol` 这个 feature 判断 dev 还是 prod 的——`let dev = !custom_protocol;`。没开它，编出来的是 dev 壳：启动时去连 `build.devUrl`，也就是 `http://localhost:1422`，`frontendDist` 指向的 `dist/**` 压根不会内联进去。用户双击后看到的是「无法访问此页面 / localhost 拒绝连接」。

所以重建可交付的 exe 一律用：

    cargo build --release --features custom-protocol

自查两条：exe 体积会明显变大；拿二进制探一眼，`index-<hash>.js` 这样的文件名应该能在 exe 字节里搜到，搜不到就是 dev 壳。

另外两条硬经验：重建前先 `Stop-Process -Name reelix -Force`，否则 `cargo` 会以 `os error 5 拒绝访问` 死在覆盖 exe 那一步；编完核对 `dist/**` 与 `target/release/reelix.exe` 的时间戳都晚于所有源码，再确认桌面快捷方式 `C:\Users\ASUS\Desktop\Reelix.lnk` 的 TargetPath 与 IconLocation 都指着这次新编的那份。
