# 16 · 素材与依赖审计

审计日期：2026-10-17。范围：3D 空间识别、剪辑、视频语音转字幕三项能力所需的二进制、模型、源码与代码接线状态。

## 一、结论

三项能力**素材层面已全部到位**，但**代码层面都还没接上**：

| 能力 | 依赖素材 | 代码接线 | 现在能不能用 |
| --- | --- | --- | --- |
| 3D 空间识别 | 齐全（COLMAP 4.2.1 二进制 + 源码） | 未接线（0 处调用） | 命令行能用，软件里不能用 |
| 剪辑 | 基本齐全（`reelix.exe` + FFmpeg 全套） | 已接线（解码/探测/抽帧/混音/导出） | 解码与预览能用；**H.264 导出需改一行**；HEVC 导出本机不可用 |
| 视频语音转字幕 | 齐全（sherpa-onnx 1.13.8 + 228MB 模型） | 未接线（0 处调用） | 命令行能用，软件里不能用 |

## 二、3D 空间识别（COLMAP）

### 现场有什么

| 路径 | 体积 | 性质 |
| --- | --- | --- |
| `reference/tracking/colmap-bin/` | 338.8MB | **COLMAP 4.2.1 免安装二进制**（nocuda），本轮补齐 |
| `reference/tracking/colmap/` | 20.0MB | COLMAP 源码（BSD） |
| `reference/tracking/libmv/` | 13.2MB | 运动恢复结构参考源码 |
| `reference/tracking/openMVG/` | 51.5MB | SfM 参考源码 |

实测：

```
COLMAP 4.2.1 (Commit bd1fcf6 on 2026-09-29 without GPU support, boost hash maps)
```

`colmap.exe -h` 退出码 0，命令可用。入口：`reference/tracking/colmap-bin/bin/colmap.exe`，同目录 DLL 必须一起保留。

### 还缺什么

| 缺口 | 影响 | 说明 |
| --- | --- | --- |
| 代码零接线 | 软件内无法触发解算 | `scaffold/src-tauri/src` 全库搜索 `colmap` 无匹配 |
| OpenCV 4.x 二进制 | 路线 B（自研交互式追踪）做不了 | 目前只有 libmv / openMVG 源码里的 OpenCV 胶水代码，没有库 |
| three.js 前端依赖 | 三维预览做不了 | `scaffold/package.json` 只有 React / zustand，没有 three / r3f / drei / troika；`reference/3d/` 只是参考源码 |
| CUDA 版（可选） | 解算更快 | 本机有 RTX 4070 Laptop；CUDA 包约 395.5MB，按 docs/10 走可选组件，不进主包 |

### 接线位置

按 [10-特效合成与空间识别.md](10-特效合成与空间识别.md) 路线 A：COLMAP 作为 **sidecar 独立进程**调用（BSD，可随包分发二进制），`feature_extractor → exhaustive_matcher → mapper` 三步，输出相机 JSON 给前端。主安装包只带自研部分，COLMAP 走可选组件。

## 三、剪辑（FFmpeg）

### 现场有什么

| 路径 | 体积 | 说明 |
| --- | --- | --- |
| `scaffold/src-tauri/target/release/reelix.exe` | 3.27MB | 主程序（2026-10-17 16:02） |
| `scaffold/src-tauri/ffmpeg/` | 153.8MB | 本轮补齐：FFmpeg + FFprobe + 7 个 DLL |

FFmpeg 版本：`N-127579-g5cb9fcd211`（2026-10-16），来源 `BtbN/FFmpeg-Builds` 的 **LGPL 共享版**。

已实测通过：

- 编码：`-c:v h264_mf` 出 MP4，退出码 0
- 探测：`ffprobe` 读出 `h264,320,240,25/1`
- 解码：抽帧到 RGBA 裸流，退出码 0
- 音频：AAC 编码可用

代码侧已有完整链路：`compositor/decode.rs`（解帧、缩略图）、`media/probe.rs`（ffprobe）、`media/audio.rs`（音频读取与混音）、`commands/export.rs`（RGBA 直灌编码）。

### 还缺什么

| 缺口 | 影响 | 处理建议 |
| --- | --- | --- |
| LGPL 构建没有 `libx264` / `libx265` | **导出直接失败**：`export.rs` 第 285 行硬编码这两个名字 | 改成 `h264_mf`（LGPL 合规，本机实测可用）；HEVC 需能力检测，`hevc_mf` 本机报 `0x80004005`，不可用时回退或提示 |
| 153.8MB 超预算 | 安装包守不住 150MB 红线（FFmpeg 预算 35MB） | 正式发版前自编译裁剪：只留 H.264 / HEVC / ProRes / AAC / MP3 / FLAC，关掉其余编解码器与封装 |
| `-preset` / `-crf` 对硬件编码器无效 | 只会打印警告，不阻止导出 | 改 `h264_mf` 时同步换成码率/质量参数 |

> 许可证：LGPL-2.1，子进程调用，未静态链接。`COPYING.LGPLv2.1.txt`、`BUILD-INFO.txt`（含完整 configure 参数与源码获取途径）已随目录放入，符合 [06](06-参考项目与许可边界.md) 与 [07](07-安装与打包.md) 的要求。

## 四、视频语音转字幕（sherpa-onnx）

### 现场有什么

| 路径 | 体积 | 说明 |
| --- | --- | --- |
| `reference/asr/bin/sherpa-onnx-*.exe` | 约 4.5MB | 4 个命令行工具（离线识别、VAD+识别、VAD、版本） |
| `reference/asr/bin/onnxruntime.dll` | 17.1MB | 推理运行时 |
| `reference/asr/models/model.int8.onnx` | 228.1MB | 中文离线识别模型（int8 量化） |
| `reference/asr/models/silero_vad.onnx` | 0.6MB | 语音活动检测，用于切句 |

实测：

```
sherpa-onnx version : 1.13.8
onnxruntime version : 1.28.2
```

二进制与模型齐全，命令行可直接跑。

### 还缺什么

| 缺口 | 影响 | 说明 |
| --- | --- | --- |
| 代码零接线 | 软件里没有「生成字幕」入口 | `scaffold` 全库搜索 `sherpa` / `asr` / `字幕` 在 Rust 侧 0 匹配 |
| 字幕数据模型与 UI | 即使识别出文字也无处落 | 时间线目前没有字幕轨类型，前端没有字幕面板 |
| 文档口径冲突 | 影响是否该做 | [01-立项规划书.md](01-立项规划书.md) 第 98 行把「自动字幕」列入「AI 功能，整个产品线不做」；用户已明确要求保留离线转写。需在文档里改为「离线语音转写，非生成式 AI」或明确例外 |

### 接线位置

1. 用 `ffmpeg.exe` 从视频抽 16kHz 单声道 WAV（FFmpeg 已就位）。
2. 调 `sherpa-onnx-vad-with-offline-asr.exe`，带 `silero_vad.onnx` + `model.int8.onnx` + `tokens.txt`。
3. 输出带时间戳的文本 → 字幕轨（新增 `SubtitleTrack` 或复用文本层 + 时间区间）。
4. 全程本地进程，不联网。
