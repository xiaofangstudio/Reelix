Reelix 的底座是两份现成的开源项目。这份文档定义**能拿什么、绝对不能拿什么**。任何一次「我要不要抄这段」的犹豫，答案在这里。

## 二、Clypra：能拿什么

Clypra 是一个已经跑通的完整剪辑器（v1.5.9，MIT）。它是 Reelix 剪辑侧的主参考，**MIT 许可允许直接改造并入**。

### 2.1 强烈建议直接借鉴的部分

| Clypra 位置 | 内容 | 在 Reelix 怎么用 |
| --- | --- | --- |
| `src/core/timeline/` | 时间线模型：片段、轨道、源时间映射、变速曲线、复合片段 | Reelix 时间线模型的直接起点 |
| `src/core/timeline/compoundClips.ts` | 复合片段（预合成）实现 | Reelix 复合片段的基础 |
| `src/core/history/commands/` | 撤销栈的命令模式实现 | Reelix 共享撤销栈的基础 |
| `src/core/evaluation/` | 参数求值 | 与 Reelix 关键帧引擎对接 |
| `src/types/keyframes.ts`、`curves.ts` | 关键帧与曲线类型定义 | Reelix 关键帧引擎的起点 |
| `src-tauri/src/engine/graph/` | **Rust 侧的图求值引擎**：`graph.rs`、`node.rs`、`executor.rs`、`cache.rs`、`resource_pool.rs` | **这是最有价值的发现**。Clypra 已经在 Rust 侧实现了节点图求值与缓存，Reelix 的统一图模型可以直接站在它上面 |
| `src-tauri/src/engine/decoder.rs` + `engine/planner/` | 解码器与渲染计划 | Reelix 解码器池的基础 |
| `src-tauri/src/engine/scheduler.rs` | 求值调度 | Reelix 并行求值的基础 |
| `src-tauri/src/wgpu_compositor/multi_track_composer.rs` | 多轨 GPU 合成 | Reelix 合成器的基础 |
| `src-tauri/src/wgpu_compositor/transition_pipeline.rs` | GPU 转场 | 直接可用 |
| `src-tauri/src/wgpu_compositor/chroma_key.rs` | GPU 色键 | 直接可用 |
| `src-tauri/src/wgpu_compositor/lut_parser.rs`、`lut_texture.rs` | LUT 解析与应用 | 直接可用 |
| `src-tauri/src/wgpu_compositor/curves.rs` | GPU 曲线调色 | 直接可用 |
| `src-tauri/src/wgpu_compositor/scopes.rs` | 示波器 | 直接可用 |
| `src-tauri/src/wgpu_compositor/texture_pool.rs`、`frame_cache.rs` | 纹理池与帧缓存 | 直接可用 |
| `src-tauri/src/thumbnail_engine/` | 缩略图与胶片带（含 `pyramid.rs` 金字塔、`mmap_cache.rs` 内存映射缓存） | 直接可用 |
| `src-tauri/src/audio/` | 音频解码、混音、环形缓冲 | 直接可用 |
| `src-tauri/src/shaders/*.wgsl` | 全部 WGSL 着色器 | 直接可用 |
| `src/lib/timecode.ts` | 时间码处理 | 直接可用 |

### 2.2 参考思路、但必须自己重写的部分

| Clypra 位置 | 为什么不直接用 |
| --- | --- |
| `src/components/**` | 界面必须全中文、必须换配色、必须按 Reelix 的四区布局重做。**只参考交互，不复制样式** |
| `src/features/*` | 特效与素材库功能，Reelix 首版不需要那么多。**选择性移植，不要整包搬** |
| `src/lib/project/` | 项目文件格式要按 Reelix 的 `.reelix` 重新设计 |

### 2.3 必须完全剔除的部分（重要）

Clypra 里有几块东西，Reelix **一个字都不能要**：

| Clypra 位置 | 内容 | 为什么剔除 |
| --- | --- | --- |
| `src-tauri/src/ai/`（`mediapipe_tracker.rs`、`model_manager.rs`） | AI 人体跟踪 | **Reelix 不带任何 AI 功能**，整块删除 |
| `src/core/telemetry/` + `docs/performance-telemetry.md` | **性能遥测，会把数据上报到 Clypra 的 Studio 管理后台** | Reelix **绝不上报任何数据**。整块删除，一个字节都不留 |
| `src-tauri/src/transfer/`（`device.rs`、`discovery.rs`、`server.rs`、`session.rs`） | 手机传输（局域网起服务） | Reelix 不做跨设备传输，**且这会让软件在局域网上监听端口**，删除 |
| `ios/`、`android/`、`capacitor.config.ts` | 移动端 | Reelix 只做 Windows 桌面 |
| `src-tauri/tauri.microsoftstore.conf.json` | 微软商店配置 | Reelix 只发 MSI |
| `src-tauri/src/diagnostics/crash_handler.rs` | 崩溃上报 | 不做任何上报 |
| `src/lib/api/` | 如果有任何联网 API 调用 | Reelix **没有网络行为** |

**判据：任何会往外发数据、任何会开网络监听、任何带 AI 的模块，一律不移植。** 移植前先全局搜一遍 `reqwest`、`http`、`fetch`、`upload`、`report`、`telemetry`。

### 2.4 移植时的注意事项

- Clypra 的 `engine/graph/` 虽然是好底子，但它是为「渲染计划」设计的，Reelix 需要的是「通用合成图」。**移植时要看清它的抽象层次是否够通用**，不够就在它上面重做一层，不要硬改。
- Clypra 的 `wgpu_compositor` 依赖 `wgpu`，Reelix 也用 `wgpu`，版本要对齐。
- **FFmpeg 是 LGPL-2.1，只能动态链接。** Clypra 用 `scripts/setup-ffmpeg.sh` 与 sidecar 方式处理，Reelix 照做，并且必须保留 LGPL 许可证文件与源码获取途径说明。
- Clypra 的 `package.json` 里有一堆 `@fontsource/*` 字体包（那是把字体塞进**界面**）。**Reelix 一个都不要**，界面字体用系统栈。**内容层**字体库是另一回事：随包内置、走 SIL OFL 等商用免费许可，见 [09-3D摄像机与素材库.md](09-3D摄像机与素材库.md) 第三节。

## 三、Gaffer：能借鉴什么

Gaffer 是工业级 VFX 软件（BSD-3-Clause），**技术栈是 C++ 与 Python，和 Reelix 的 Rust + TS 完全不同，代码不可能并入**。它提供的是**模型与思想**。

### 3.1 要借鉴的概念

| Gaffer 概念 | 在 Reelix 的对应 |
| --- | --- |
| **延迟求值（Deferred Evaluation）** | Reelix 求值模型的核心。不主动算，被问才算。见 [04](04-剪辑与特效融合设计.md) 第五节 |
| **节点（Node）与插槽（Plug）** | Reelix 的 `GraphNode` 与 `Plug`。插槽是类型化的 |
| **多线程求值引擎** | Reelix 的 `graph/scheduler.rs`。任务图调度，每个节点独立加锁，不用一把大锁 |
| **Box / Reference（盒子）** | Reelix 的**复合片段**。把一组节点打包成一个可复用单元 |
| **图即数据，界面只是视图** | Reelix「内部是图，界面是层」的直接来源——图只在内部求值，界面永远只有效果栈 |
| **节点的「旁路」（Bypass）** | Reelix 节点的 `bypassed` 状态：旁路后数据直通，节点保留 |
| **表达式与脚本驱动参数** | Reelix 首版不做脚本，但参数系统要预留「可被表达式驱动」的余地 |

> **⚠️ 必须知道的一件事：Gaffer 不含相机追踪 / SfM。** Gaffer 是**合成与渲染的编排框架**，它**消费**别人算好的相机数据，自己**不做解算**——工业流程里追踪数据来自 3DEqualizer / PFTrack / SynthEyes / Nuke 的 CameraTracker 这类独立解算器。所以「识别扫描 3D 空间场景」这块，**Gaffer 帮不上忙**，Reelix 必须另找方案：空间识别走 **COLMAP（BSD）+ 自研交互式追踪**。完整方案见 [10-特效合成与空间识别.md](10-特效合成与空间识别.md)。

### 3.2 不要借鉴的部分

| Gaffer 的部分 | 原因 |
| --- | --- |
| `src/` 下全部 C++ 代码 | 技术栈不同，且规模巨大 |
| `python/` 下的节点实现 | 同上；且 Reelix 首版不做脚本 |
| `arnoldPlugins/`、`usdSchemas/`、Cycles 相关 | 是**离线渲染器**的插件与 USD 模式定义，Reelix 不接第三方渲染器 |
| `SConstruct` 构建系统 | 用 scons，和 Reelix 的 cargo + vite 完全不同 |
| `python/GafferScene/` 的节点实现代码 | 它的三维场景是**面向渲染农场**的重型结构（USD / 场景图 / 几何体），与 Reelix 要的「从实拍反推相机与点云」不是一回事。**结构可看，代码不抄** |

> **注意一处旧表述已作废：** 本节原先写「Reelix 只处理二维图像合成」「Reelix 不做三维」。**这是错的**——用户明确要求「识别扫描 3D 空间场景」必须有。正确的表述是：**Reelix 不做自由建模与第三方渲染器接入，但必做从实拍反推相机与场景结构（SfM）以及三维元素的空间贴合。**

### 3.3 参考路径

Gaffer 里值得翻阅的是 `include/Gaffer/` 与 `python/GafferImage/` 的**结构**（看它怎么组织节点类型与插槽），以及 `src/Gaffer/` 里求值引擎与调度器的组织方式。**只看结构，不抄代码。**

| **MIT** | ✅ 可以 | 保留版权声明与许可证文本 |
| **BSD-2 / BSD-3** | ✅ 可以 | 保留版权声明与许可证文本 |
| **Apache-2.0** | ✅ 可以 | 保留 NOTICE 文件；注意专利授权条款 |

## 五、移植操作流程

每次从 Clypra 移植一块代码，按这个流程走：

1. **确认许可证**：查上面的白名单表。不在表里的，先问用户。
2. **确认没有联网、没有 AI**：全局搜 `reqwest`、`http`、`fetch`、`telemetry`、`report`、`upload`、`ai`。
3. **确认依赖可接受**：这块代码引入了哪些新 crate / npm 包？逐个查许可。
4. **重命名与改写**：把 Clypra 的命名换成 Reelix 的命名（见 [AGENTS.md](../AGENTS.md) 术语统一表），把英文注释与文案换成中文。
5. **换配色**：任何带颜色的代码，换成 Reelix 的令牌（`--rl-*`）。**Reelix 的界面强调色是浅绿 `#26734f`（填充按钮 `#57c08f`），不是蓝色。** 小方品牌蓝 `#6fc0ff` 只用于 logo 与「关于」页。**不要留任何紫色、橙色或 Clypra 自己的强调色。** 唯一权威是 `scaffold/src/styles/tokens.css`。
6. **加进 `THIRD_PARTY_NOTICES.md`**：写明来源、许可证、修改了什么。
