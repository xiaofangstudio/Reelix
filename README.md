# Reelix

**特效合成软件。** 主对标 After Effects / Fusion / Nuke，副对标 Premiere Pro。

剪辑是它的附属能力，合成才是它的身份——因为做合成必须能摆镜头顺序，所以剪辑轨道内建在同一个软件里，而不是另做一个。

## 它解决什么问题

用 After Effects 加 Premiere 做片子，工作流通常是这样：

1. 在 Premiere 里剪好时间线
2. 发现某个镜头需要合成
3. 单独导出，或跳转到 After Effects
4. 新建合成、摆图层、加效果、打关键帧
5. 渲染导出，再导回 Premiere
6. 发现时间点对不上，或者长度要改
7. 回 After Effects 改，重新渲染，重新导回
8. 重复 3 到 7

被吃掉的不是创作时间，是等待。更难缠的是心智负担：两个时间线、两个工程文件、两套关键帧、两套撤销栈，还要时刻记住「我现在在哪个软件里」。

Reelix 的做法是**同一个项目、同一份数据、同一个窗口**：

- 一个 `.reelix` 工程文件，不是两个
- 一份数据模型，内部是一张有向无环图做求值
- 一套关键帧引擎，片段参数与效果参数共用
- 一套撤销栈，剪辑操作与特效操作在同一个历史里
- 时间线、效果栈、曲线编辑器实时双向联动

## 内部是一张图，界面只有一层

Reelix 不做节点式界面。

给一个片段加特效，就是在它的**效果栈**里加一张卡片，自上而下依次叠加；给整条序列调色，就是把调色挂在序列上。用户看到的是时间线、效果栈、曲线编辑器和监视器，看不到节点，也看不到连线。

图只在内部把效果栈编译出来求值。同一份数据，几种视图：时间线按时间轴排列，效果栈按处理顺序排列，曲线编辑器管关键帧；选中一个片段，它们立刻同步。

## 能力

### 合成（主体）

- 图层合成与效果栈，参数实时影响预览
- 蒙版与形状遮罩：钢笔、矩形、椭圆、羽化、扩展、反转、遮罩跟踪
- 色度抠图：取色、容差、边缘羽化、溢色抑制、去杂边
- 粒子系统：发射器、发射速率、寿命、初速度、重力、尺寸与透明度随生命周期变化、湍流
- 调色与 LUT、基础色彩空间转换、示波器
- 文字与图形层：标题、字幕、基础矢量形状、三维文字
- 预设特效与素材库

### 空间识别（地基）

- 从实拍视频反推摄像机运动与场景三维结构：相机追踪 / SfM / 三维重建
- 解算出的相机直接作为可操作的三维摄像机
- 视频 2D→3D 空间转换：相机反投与深度分层，把平面画面变成有深度、可摆三维元素的空间
- 三维场景、三维平面、点云；稠密重建（MVS）作为可选深化

### 动画

- 关键帧 + 曲线编辑器，任何数值参数都能打帧
- 共享曲线引擎：片段、效果、三维对象用同一套
- 预设动效库与缓动曲线

### 剪辑（附属）

- 多轨时间线：修剪、拖拽、切割、吸附、排列
- 复合片段（预合成）
- 帧精确的音画同步
- 音频波形、多轨音量、淡入淡出、麦克风录音

### 输出

- H.264 / ProRes 等常用格式
- 可选分辨率、码率、色彩空间
- GPU 合成与硬件加速解码（Windows 上走 D3D11VA）
- 导出走 wgpu 管线，不用 WebGL 截屏

## 技术底座

| 层 | 选型 |
| --- | --- |
| 外壳 | Tauri v2 |
| 后端 | Rust：解码、合成、导出、文件读写、IPC |
| 前端 | React 18 + TypeScript |
| 构建 | Vite 5 |
| 状态 | Zustand |
| 样式 | 原生 CSS 变量 + 手写 CSS |
| GPU | WebGPU（wgpu） |
| 3D 预览 | three + @react-three/fiber + drei（仅预览与操作器） |
| 空间解算 | 自研交互式（Rust + OpenCV）+ COLMAP sidecar |
| 解码与编码 | FFmpeg（LGPL-2.1，仅动态链接） |

所有重活都在 Rust 侧。前端只做界面与交互，不做解码、逐帧合成与大文件读取。

## 界面

- 主题：中性白 + 浅绿，默认浅色
- 强调色 `#26734f`，填充按钮 `#57c08f`
- 小方品牌蓝 `#6fc0ff` 只用于 logo
- 不使用节点式界面，不做第二强调色
